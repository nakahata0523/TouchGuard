# Touchpad filter (C)

Linux evdev/uinput用。制限対象は、移動後の有効期間外に始まった1本指タップです。
物理クリック、複数指タップ、スクロール、クリックの指本数判定、タップドラッグは
OS（GNOME/libinputなど）に任せます。独自のクリック生成やクリック用仮想マウスは使いません。

## ビルドと実行

```sh
cc -O2 -std=c11 -Wall -Wextra -Wpedantic touchpad_filter.c -lm -o touchpad_filter
sudo ./touchpad_filter /dev/input/eventN
```

実際のタッチパッドのパスに置き換えてください。起動時は指を離してください。
入力デバイスの読み取りと /dev/uinput の書き込み権限が必要です。
Python版との同時起動は避けてください。終了はCtrl+CまたはSIGTERMです。
サービスで実行している場合、更新後に再起動します。

```sh
sudo systemctl restart touchpad-filter.service
```

OS側の「タップでクリック」「タップドラッグ」を有効にしてください。
このプログラムはOS設定を変更しません。OS側で無効な操作は追加しません。
元のPython版は旧方式のままです。

## 操作ごとの扱い

- 移動後2秒以内に始まった接触は、その開始からOSへ転送します。
- 有効期間外の1本指接触だけ、移動かタップかを判別するため一時保留します。
  開始位置から0.3mm移動したら、保留分を含めて転送します。
  移動せず1本指のまま離れた場合は接触を破棄します。
- 2本以上の指、または物理ボタンの押下・解放を検出した場合は、時間や移動条件を
  待たずに保留を解除します。ボタンは元の接触情報と同じ仮想タッチパッドに転送し、
  OSによる二本指押し込みの右クリック判定などを維持します。
- 許可した短い接触後の再接触には300msの継続期間を設け、OSのタップドラッグを
  妨げないようにします。複数指タップ後のドラッグにも適用します。
  実際のタップ・ドラッグの認識時間、ボタン割り当て、解除動作はOS側が決定します。
- ログは既定で省略します。`--verbose` で破棄ログを表示します。

evdevではOSのタップ判定より前に処理するため、すべての接触を即時転送しつつ
後からタップだけ取り消すことはできません。そのため、有効期間外の最初の1本指移動には
最大0.3mmの判定待ちがあります。保留フレームの再送時刻も実入力とは異なります。
物理ボタンや複数指を最初から検出したフレームには、独自の時間・距離制限を掛けません。

## オプションの既定値

| オプション | 既定値 | 現在の用途 |
|---|---:|---|
| `--click-window-ms` | 2000 | 最終移動から接触開始までのタップ許可期間 |
| `--min-move-mm` | 0.3 | 移動として保留を解除する距離 |
| `--threshold-ms` | 30 | 有効な移動時刻を記録するための接触時間。複数指・物理ボタンの待ち時間ではない |
| `--motion-step-mm` | 0.1 | 最終移動時刻を更新するフレーム間移動量 |
| `--tap-max-ms` | 250 | OSのドラッグ継続用として扱う接触の最大時間 |
| `--tap-slop-mm` | 1.5 | 同継続判定に使う1本指接触の最大変位 |
| `--drag-window-ms` | 300 | 許可済み接触の後に続く接触を転送する期間 |

旧版と一部オプションの用途が変わっています。OS側のタップ判定は変更しません。
数値は有限の正数に限定します。SYN_DROPPEDやバッファ上限超過では終了します。

## テスト

```sh
cc -O2 -std=c11 -Wall -Wextra -Wpedantic touchpad_filter_test.c -lm -o /tmp/touchpad_filter_test
/tmp/touchpad_filter_test
```

無移動の1本指タップ破棄、移動後の転送、短い複数指接触、2本目の指と物理ボタンによる
即時保留解除、ドラッグ継続、転送イベントの一致を検証します。
実機のGNOME/libinputでの操作感は別途確認が必要です。
